# HexFlow Copilot — Agent Engineering Rules

You are working on **HexFlow Copilot**, subtitled “A Creative Studio concept for HexCoded.” Tagline: *Turn creative intent into executable workflows.*

## Before you edit

1. Inspect the repository first. Read `package.json`, configuration, `src/`, tests, README, and git status. Do not assume the repo is empty.
2. Preserve useful existing work. Do not delete or rewrite unrelated files.
3. Read this file plus `docs/PRODUCT_SPEC.md` and `docs/ARCHITECTURE.md` before substantial changes.
4. Prefer the smallest change that satisfies the current task. Do not implement ahead of the active prompt.

## Stack (locked)

- Next.js App Router, strict TypeScript, Tailwind CSS
- `@xyflow/react` for the node canvas
- Zustand for client state
- Zod as the source of truth for runtime schemas
- Vitest + React Testing Library for unit/component tests
- Playwright for one end-to-end smoke path
- Package manager: **npm only**

## Product and security constraints

- No database, authentication, API keys, paid services, or external generation providers in this prototype.
- Persistence is browser `localStorage` only.
- Real local LLM calls go through **Ollama** from **server-side route handlers only**.
- Public deployment uses a **deterministic interactive demo engine** (`AI_MODE=demo`).
- Never expose `OLLAMA_BASE_URL` (or other Ollama server config) to the client.
- Never accept an Ollama URL from request data or `NEXT_PUBLIC_*` variables.
- Never execute arbitrary code, shell commands, or node-supplied JavaScript (`eval`, `Function`, etc.).
- Every workflow graph must remain a **DAG**.
- Media-generation nodes are provider placeholders and must be labelled honestly (`simulated: true`, “needs provider”).
- The public UI must clearly show **Demo engine** when applicable and must never pretend simulated media was generated by a real provider.

## AI modes

| Mode | Behavior |
|------|----------|
| `demo` | Always use the deterministic demo engine. No Ollama network calls. |
| `ollama` | Require Ollama; return a useful error if unavailable. |
| `auto` | Use Ollama if reachable; otherwise fall back to demo for connection/timeout/unavailable-model only. |

Vercel / public deploys must set `AI_MODE=demo` explicitly. Vercel cannot reach Ollama on a laptop.

## Validation and quality

- Validate all workflow / brief / edit / execution payloads with **Zod** before use.
- Validate graph invariants (unique IDs, endpoints, no cycles, reachability) before persisting to client state, rendering in React Flow, or executing nodes.
- After each change, run the **relevant** tests (`npm run test`, and `typecheck` / `lint` / `build` when the task asks).
- Do not claim tests passed unless you actually ran them.
