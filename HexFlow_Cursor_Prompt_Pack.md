# HexFlow Copilot — Cursor Build Prompt Pack

Use these prompts one at a time in Cursor Agent mode. Do not paste all prompts at once. Let Cursor complete the task, review the changes, run the requested checks, and only then move to the next prompt.

## Important deployment constraint

A public Vercel deployment cannot call Ollama running on your laptop. This project therefore has two honest operating modes:

- Ollama mode: real LLM planning, editing, and text-node execution while running locally.
- Demo mode: deterministic but genuinely interactive workflow planning, graph editing, and node execution for the public deployment.

The public application must clearly display “Demo engine” and must never pretend that simulated media was generated by a real provider. The core product interaction—turning a brief into a graph and modifying the graph conversationally—must remain fully usable.

## Locked product decisions

- Product name: HexFlow Copilot
- Descriptor: A Creative Studio concept for HexCoded
- Tagline: Turn creative intent into executable workflows.
- Stack: Next.js App Router, TypeScript, Tailwind CSS, React Flow through @xyflow/react, Zustand, Zod, Vitest, React Testing Library, Playwright.
- Package manager: npm.
- Persistence: browser localStorage. No authentication or database in this prototype.
- Local AI: Ollama through server-side Next.js route handlers.
- Public AI: deterministic demo engine.
- No API keys, paid APIs, image-generation APIs, or video-generation APIs.
- Desktop-first layout, with a usable narrow-screen fallback.
- All generated workflows must be directed acyclic graphs.
- The product must never execute arbitrary user code or shell commands.
- The Ollama base URL comes only from a server environment variable and can never be supplied by a browser request.

## Recommended local model setup

Start with qwen3:4b because it is more practical on typical laptops:

    ollama serve
    ollama pull qwen3:4b
    ollama list

Then create .env.local:

    AI_MODE=ollama
    OLLAMA_BASE_URL=http://127.0.0.1:11434
    OLLAMA_MODEL=qwen3:4b
    OLLAMA_TIMEOUT_MS=120000
    OLLAMA_KEEP_ALIVE=10m

If the laptop has sufficient RAM or VRAM, change only OLLAMA_MODEL to a stronger locally installed model. Do not hard-code the model inside route handlers.

For the public Vercel deployment:

    AI_MODE=demo

Do not configure a public tunnel to a personal Ollama instance for the hiring demo. The deterministic public engine is safer, faster, and reproducible; local Ollama can be demonstrated in the recording and documented in the repository.
